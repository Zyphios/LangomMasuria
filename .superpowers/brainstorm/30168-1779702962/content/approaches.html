3 podejścia do budowy Lagom Masuria — każde jako osobne kontenery Docker

A

React + Node/Express + PostgreSQL ⭐ Rekomendowane

Trzy osobne kontenery Docker: React (Vite) jako frontend SPA, Express.js jako REST API backend, PostgreSQL jako baza danych. Panel admina jako osobna trasa w React.

Zalety

  • Czyste oddzielenie: frontend / backend / db
  • Idealnie pasuje do wymagania "3 kontenery"
  • Node.js = łatwa integracja e-mail (Nodemailer)
  • Duże community, wiele gotowych bibliotek
  • Łatwe zarządzanie i18n (react-i18next)

Wady

  • SPA — słabszy SEO bez SSR (można dodać później)
  • Dwa osobne projekty JS do utrzymania
B

Next.js (fullstack) + PostgreSQL

Jeden kontener Next.js obsługuje zarówno frontend (SSR/SSG) jak i API routes jako backend. Drugi kontener to PostgreSQL. Opcjonalnie Nginx jako proxy.

Zalety

  • Jeden codebase — mniej plików konfiguracyjnych
  • Lepszy SEO dzięki Server-Side Rendering
  • Szybsza pierwsza strona (ważne dla turystów)

Wady

  • Frontend i backend pomieszane w jednym projekcie
  • Trudniejsze skalowanie oddzielnie
  • Nie spełnia dosłownie wymagania "osobny backend"
C

React + FastAPI (Python) + PostgreSQL

React (Vite) frontend, FastAPI backend w Pythonie, PostgreSQL baza. Trzy kontenery Docker.

Zalety

  • FastAPI bardzo szybkie i z auto-dokumentacją (Swagger)
  • Python — łatwe dodanie AI/ML w przyszłości

Wady

  • Dwa różne języki (JS + Python) — trudniejsze utrzymanie
  • Większy narzut konfiguracyjny
